# 📘 Milestone 1 – Week 1–2: Data Understanding, Anomaly Generation & Data Cleaning

### 🟦 1. Overview

This milestone serves as the foundation of the project. We focused on auditing the dataset structure, intentionally introducing synthetic real-world anomalies, and engineering a robust cleaning pipeline to ensure the data is **consistent, accurate, and model-ready**. 🚀

### 🟦 2. Dataset Understanding 🔍

---

### 🟦 3. Anomaly Generation (`introduce_anamolies.py`) 🛠️

To simulate the "messy" data found in real-world supply chains, we artificially injected several issues:

* **Missing Values:** Added random `NaN` values to `supplier_rating` and `order_quantity`. 🚫
* **Duplicate Rows:** Inserted clones to mimic data merging glitches. 👯
* **Datatype Errors:** Placed strings like `"error_value"` into numeric columns. ⚠️
* **Extreme Outliers:** Set unrealistic values (e.g., `shipping_distance_km = 99999`). 📈
* **Logical Flaws:** Set `actual_delivery_date` earlier than the `order_date`. ⏳

**📄 Output File:** `dataset_with_anomalies.xlsx`

---

### 🟦 4. Data Cleaning (`clean_anamolies.py`) 🧹

After creating the issues, we applied a systematic recovery process:

* **Deduplication:** Applied `drop_duplicates()` to remove redundant rows. ♻️
* **Type Correction:** Converted `"error_value"` entries to `NaN` and restored numeric types. ⚙️
* **Imputation:** * Used **Median** for numeric columns (resilient to outliers). 🔢
* Used **Mode** for categorical labels. 🏷️


* **Date Repair:** Removed logically impossible delivery dates. 🗓️
* **Outlier Capping:** Applied **IQR-based capping** on distance and quantity fields. 📐
* **Feature Engineering:** Calculated `delivery_days` (Actual Delivery - Order Date). 🏗️

**📄 Output File:** `cleaned_dataset.xlsx`
